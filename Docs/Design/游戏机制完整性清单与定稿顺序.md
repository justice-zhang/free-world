# 游戏机制完整性清单与定稿顺序

- 文档版本：`0.1.0`
- 文档状态：跨模块工作索引；不直接取代各 `Systems` 权威文件
- 适用范围：从正式世界观基线进入完整玩法机制定稿
- 上级索引：[《剑起青岚》正式游戏系统方案](剑起青岚_正式游戏系统方案.md)
- 技术边界：[内容与技术边界](Systems/08_内容与技术边界.md)

## 1. 目的

本文件回答三个问题：完整游戏还缺哪些机制、哪些规则必须先决定、每项结论最终应写回哪个权威
模块。它只保存覆盖状态、依赖顺序和当前待评审方案；一项机制只有写回对应 `Systems` 文件并标记
为 `ACCEPTED`，才成为正式规则。

“完整机制”不等于一次填满所有平衡数字。一个系统至少要说明：

1. 玩家在其中作什么决定；
2. 系统何时进入、如何推进、何时退出；
3. 输入、状态、产出、失败和异常情况；
4. 与角色、构筑、关卡、结算和局外成长的接口；
5. UI 必须展示什么，哪些信息不得隐藏；
6. 哪些数据入存档，哪些只在单局存在；
7. 当前冻结框架能否表达，是否需要 Change Request；
8. 灰盒指标、验收条件和需要观测的数据。

## 3. 当前最需要消除的结构矛盾

### 3.1 构筑究竟有两层还是三层

用户已确认的核心构筑是“有限武器槽 + 有限心法槽 + 固定器法合鸣”。现有产品文档又从旧大纲带入
了“战场奇物”，但没有确定它是否占槽、如何取得、如何升级，也没有冻结框架 Schema 支持。

在这一点定案以前，不能同时围绕两层构筑调整升级节奏，又默认第三层奇物会提供大量规则修正。

### 3.2 草稿属性与冻结属性不一致

旧大纲列出暴击伤害、投射物速度、经验获取等属性；冻结框架只有十四项公共属性。正式设计应优先
使用现有属性，确有普遍价值的新增项再单独提出 CR，不能在内容文件里使用运行时不存在的属性。

### 3.3 角色差异与公共池的强度边界尚未量化

角色可以改变本命器法形态，但公共器法脱离角色也必须完整成立。后续需要建立“公共版本已完成，
角色联动再横向改变”的验收标尺，避免角色联动变成公共内容缺失的另一半。

### 3.4 随机池保护不能等同于保送最优构筑

需要同时保证已有内容能够成长、至少一条合鸣路线现实可达，又不能按当前构筑直接发放最优答案。
因此必须先规定候选槽的保底职责，再讨论权重和幸运。

## 4. 定稿依赖顺序

```text
A. 构筑容量与升级选择
→ B. 基础战斗、经验、拾取和局内奖励
→ C. 角色技、固有特性与行脉图
→ D. 敌人、精英、导演、地图目标与 Boss
→ E. 胜败结算、局外经济、内容解锁与旧庭
→ F. 难度、重访、挑战模式与奖励倍率
→ G. UI、教学、可访问性、内容规模与平衡验收
```

先定 A，是因为槽位和升级总量直接决定单局目标等级、经验曲线、宝匣时点、敌人奖励与 30 分钟
节奏。先做角色或批量武器，会反过来被容量规则推翻。

## 5. 第一轮决策包：构筑容量与升级选择

本节状态：除已注明的既有约束外，均为 `PROPOSED`；数字为灰盒起测建议

### 5.1 推荐的基础构筑层

| 层级 | 推荐规则 | 理由 |
|---|---|---|
| 武器 | `4` 槽，角色本命武器固定占 `1` 槽 | 保留三次自由武器选择，使开局身份明显且每次取得仍有代价 |
| 心法 | `4` 槽，角色本命心法固定占 `1` 槽 | 与武器形成对称、可读的器法构筑 |
| 角色技 | 统一一个角色技位，不占上述槽位 | 已接受规则 |
| 行脉图 | 局前配置，不进入局内随机池 | 已接受规则 |
| 即时灵物 | 接触即生效，不占槽、不进入升级候选 | 为恢复、吸取、清弹等战场节奏服务 |
| 战场奇物 | 不纳入首版基础构筑 | 第三套永久局内槽会稀释器法核心，且当前框架没有对应 Schema |

“不纳入首版”不是永久删除奇物概念。若四武器、四心法仍不足以支持规则型奖励，再以通用 Trait
式额外构筑层提出独立方案和 CR；不能先把奇物写进正式内容，再补它为何存在。

### 5.2 推荐等级结构

- 武器统一最高 `8` 级；
- 心法统一最高 `5` 级；
- 新取得内容从 `1` 级开始；
- 角色本命武器与本命心法开局免费处于 `1` 级；
- 非本命内容一旦取得，基础模式不允许替换或移除；
- 显化替换满级武器，配套心法保留满级，不产生第二阶段普通升级；
- 每件武器基础上只对应一条标准显化配方；一部心法可以参与多条不同武器配方。

这一结构下，满四武器、四心法共需 `52` 个内容等级；扣除开局免费的两个 1 级，整局完全升满
需要 `50` 次有效成长。若 30 分钟关卡目标落在约 `48—55` 次等级选择，再叠加宝匣补偿和地图奖励，
完整构筑可以在后段出现，但不会在中段自动完成。

### 5.3 推荐升级候选规则

- 每次升级暂停模拟并展示 `3` 个不同候选；
- 候选只包含新武器、新心法、已有武器升级和已有心法升级；显化只来自宝匣；
- 只要仍有未满级的已持有内容，三个位置中至少一个来自“已有内容升级”；
- 新内容仍按权重抽取，不保证配方另一半；已持有某半配方时，另一半获得有限软权重；
- 地域倾向、角色标签和新内容保护只能改变权重，不能把某项变成必出；所有权重修正设置总上限；
- 满槽后不再出现对应类别的新内容；基础模式不提供临时替换；
- 本命武器和心法可以正常获得升级候选，但不能被局内封禁；
- 没有任何有效内容候选时进入通用兜底，具体治疗与灵砂规则在局内奖励轮定稿。

推荐初始候选控制：

| 功能 | 新存档基础次数 | 局外封顶建议 | 行为 |
|---|---:|---:|---|
| 重投 | 1 | 3 | 重新生成全部三个候选，不返还已用次数 |
| 放弃 | 1 | 2 | 结束本次升级，不取得奖励 |
| 封禁 | 0 | 2 | 排除所选 Offer 的后续出现，并立即重投；不能用于本命器法 |

次数提升属于有限候选控制，不增加伤害或无限成长。最终次数与解锁来源写入局外成长模块；现有 M6
虽有三种命令，但没有正式次数预算，因此实现前仍需 CR。

### 5.4 这一提案解决什么

- 角色固定携带一对器法后，仍有三武器、三心法的自由构筑空间；
- 单局升级总量可以反推经验曲线，而不是先凭感觉填经验数值；
- 器法合鸣仍是后段目标，宝匣不会在前十分钟频繁失去用途；
- 不引入第三套奇物槽，先验证公共武器、心法、角色技和地图目标能否支撑完整深度；
- 四槽比六槽更能抵抗公共池膨胀，也更适合有限地图中的主动探索奖励。

### 5.5 需要灰盒验证的风险

1. 固定本命占四分之一容量是否让角色之间的自由构筑过窄；
2. `50` 次有效成长能否与青岚旧庭 30 分钟节奏匹配；
3. 至少一个已有升级候选是否过度降低随机张力；
4. 没有战场奇物后，精英和地图事件是否仍有足够多样的局内奖励；
5. 心法可参与多条配方时，是否产生少数心法成为普遍最优的问题。

## 7. 状态推进规则

- 本文件中的 `PROPOSED` 数字经讨论确认后，写回对应系统模块并改为 `ACCEPTED` 或 `TUNING`；
- 尚未进行灰盒测量的倍率、概率、时间和价格不得标为平衡完成；
- 需要 Schema、存档、输入、公共 API 或 Assembly 变化的规则，在设计确认后单独建立 Change Request；
- 正式内容数量只在机制容量稳定后决定，不用批量角色或器法反向证明尚未定案的系统可行。

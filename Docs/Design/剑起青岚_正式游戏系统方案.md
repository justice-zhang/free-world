## 1. 本文档是什么

这是《剑起青岚》正式游戏设计文档包的唯一总入口。它只保存跨模块不变量、权威关系、当前内容目录
和待决队列；完整规则分别进入 `Systems`，具体角色、关卡、器法和敌人分别进入 `Content`。

跨模块的机制覆盖状态、冲突和定稿依赖由[游戏机制完整性清单与定稿顺序](游戏机制完整性清单与定稿顺序.md)
跟踪；该清单不越过各系统权威文件自行宣布规则定案。

旧的单文件方案已经转为[非权威历史归档](Archive/剑起青岚_系统方案_单文件草案_v0.7.0.md)，只用于追溯讨论，
不得与本入口或模块文件并列引用为现行规则。原始四份大纲仍是素材来源，不是正式设计基线。

## 2. 权威层级与阅读顺序

在不改变仓库 `AGENTS.md` 总优先级的前提下，本设计包内部按以下顺序解释：


- 影响当前技术 Schema、公共 API、存档或依赖方向的设计，不因写入本文就自动获得实现授权；
- 冲突无法按权威层级解决时停止实现并提交明确问题。

## 3. 产品定义

本节状态：`ACCEPTED`

《剑起青岚》是一款以单人、可离线完成为核心的俯视角中国幻想动作 Roguelite。基础战斗采用
Survivors-like 的自动武器攻击、密集敌群、局内升级和固定配方显化，并用以下层级形成自己的身份：

1. 独立角色技和可配置行脉图提供角色玩法；
2. 有限手工地图、可选目标和不同胜利条件提供关卡玩法；
3. 全公共武器、心法及器法合鸣提供跨角色构筑；
4. 青岚旧庭、重现秘境、十一脉与新生第十三脉承载世界推进；
5. 脉标、内容研习、角色阅历和有限行脉点构成局外闭环。

首发目标仍是 Windows x64 / Steam，单机核心不依赖在线服务。框架阶段只使用程序化 Placeholder。

## 4. 设计支柱

本节状态：`ACCEPTED`

### 4.1 自动攻击，但不自动游玩

普通武器自动攻击；玩家持续负责移动、角色技、升级选择、路线、地图目标、风险收益和 Boss 走位。

### 4.2 公共器法，角色另有身份

所有武器和心法都是公共内容。本命器法只表示某角色开局固定携带、且最契合其角色技和行脉图的
一对公共器法，不是专属内容类型。角色辨识度来自角色技、行脉图和角色 Trait，而不是污染公共池。

### 4.3 有限地图，而非无意义平面

主要秘境通过区域、地标、路线、敌人生态、可选事件、目标和关底结构形成差异。关卡可以是讨伐局
或生存局，不强迫所有地图共享同一种计时胜利。

### 4.4 清朗而有历史重量的中国幻想

世界可以危险、失衡和存在牺牲，但不是只有腐化与废墟。自然、器物、礼制、门派与新生命都应保留
自身理由；哲学矛盾来自如何理解和安置新生之物，而不是把未知一律写成邪恶。

### 4.5 选择产生可见后果

构筑、路线、地图目标、势力观点和终局立场都必须改变可观察的战斗、据点或叙事结果，而非只修改
隐藏百分比或换一段文字。

## 7. 已接受的世界与开局基线

本节状态：世界与开局基线 `ACCEPTED`；事故具体机制 `PROPOSED`

### 7.1 世界

- 天地灵气沿山川长期运行，形成稳定的天衡十二脉；青岚脉与其余十一脉交会最多；
- 新生异源不是污染，而是原有十二脉之外出现的第十三脉；
- 青岚宗发现其后，执法队失联，远方也开始出现短暂交叠，宗门决定只封异源、保留青岚脉；
- 青岚脉整体移境不是原定牺牲，也不是青岚封法扩张的结果：第十三脉跨过成脉临界时，沿青岚早已出现的
  多处重叠同步定形，使青岚的运行整体落到另一侧；青岚宗域等交叠最深处随之从现世消失；
- 大部分交会在事故中自然断开。宗主最后只能命剑阵关闭旧庭护阵仍维持的一处通口，防止两侧从此处
  再次失控交叠；从此人间只余十一脉；
- 数代之后，外界十一脉形成新流路，封境内旧脉与新脉也持续演化，两边重新接近，秘境入口因此在
  当代大量出现；
- 一处秘境可以在不同地点出现多个不稳定入口，但青岚旧庭拥有连通所有秘境的稳定潜力；每条路线
  仍需发现、确认并以脉标锚定。

当前事故机制首案为 `PROPOSED`：新生第十三脉自己的路径尚不完整，已经借用了青岚的一部分旧路；
青岚宗只在核心布阵封源，封法既没有沿青岚传播，也没有移动天地大脉的力量。真正改变尺度的是新脉
成形时各处既有重叠同步定形；局部封源可能促使临界恰在当时发生并影响核心落向，却不能等同于主动
封禁整条青岚。这是旧方法面对新情况的误判，不是第十三脉有意反击、幕后破坏或宗主预谋献祭全宗。

### 7.2 开局

- 陆青野偶然听见三声剑鸣并进入青岚旧庭；
- 第一声是听风的止步警告，第二声是旧庭剑阵回应，第三声是封境开始重接后、新生第十三脉第一次
  隔界回应旧庭剑鸣；
- 第一关不能直接揭晓第三声来源，只把异常作为后续主线线索；
- 首通听风后，青岚旧庭成为队伍大本营和秘境通路枢纽。

### 7.3 主线终局

后期围绕如何处理第十三脉形成三种都需承担代价的终局方向：

- `复脉归衡`：把第十三脉与青岚分开，让青岚回到原有十二脉秩序；
- `守界续封`：延续边界，以持续守护和失去交流机会换取稳定；
- `化脉新衡`：为第十三脉建立自己的稳定路径，让十二与十三共同存在，承担最大未知。

三者不是善恶按钮；具体势力选择、代价兑现和关卡后果仍需后续模块化设计。

### 7.4 势力

势力先按世界观成立，再讨论玩法岗位。首版现世四方势力分别是：与青岚宗有旧交的古老道门
太微观、在十一脉时代壮大的炼器仙城赤炉城、从薄灵之地形成的新兴山门抱朴山，以及由失乡者和
行旅者结成的不系舟。四者分别立足于旧日权威、新世技艺、地方适应与无定所之人，不与三种终局
一一绑定。

各地本土共同体和封境诸民不是统一联盟，具体地图必须独立命名。青岚旧庭则由玩家行动逐步成为
共同体，但开局不预定复兴青岚宗。商人、据点设施、角色来源、声望与内容解锁均保持 `OPEN`，不能
反过来作为四方势力成立的理由。

## 8. 已接受的构筑不变量

本节状态：`ACCEPTED`

1. 局内有有限武器槽和有限心法槽，具体数量待灰盒决定；
2. 所有武器和心法都来自公共内容池；
3. 每名角色开局固定携带一件公共武器和一部公共心法，正常占槽并正常升级；
4. 本命器法不能在局内被替换、封禁或移除，其余槽位自由构筑；
5. 角色技使用统一输入位，不进入随机池、不占器法槽，可设计为主动或自动蓄满触发；
6. 行脉图全部节点最终可解锁，但激活点数有限、免费重置、一次最多激活一个终端；
7. 特定武器与特定心法都满级后，才进入对应器法合鸣候选；
8. 中段 Boss 若存在则必掉一个显化宝匣，精英低概率掉落；
9. 宝匣从当时全部有效合鸣中随机选择一项，界面只展示最终结果，不让玩家直接选择最优解；
10. 没有有效合鸣时，宝匣提供当前有效的器法升级、治疗或其他补偿；
11. 结束本局的最终 Boss 击败判定或生存目标完成后立即结算，不再掉落无用显化媒介；
12. 特殊高品质宝匣未来可以多次结算，但不属于基础规则。

## 9. 青岚旧庭首版结论

### 9.1 已接受

- 正式 Boss 名为“守庭剑灵·听风”；
- 青岚旧庭为讨伐局；`T = 30:00` 是旧山门和 Boss 开放点，不是自动胜利点；
- 听风仍在忠实执行事故发生时宗主留下的最后闭庭命令；
- 击败为非致死结果，听风首通后留在大本营；
- 三处剑印是可选优势，不处理也能公平通关。

### 9.2 首版提案

| 剑印 | 地区 | 挑战 | 对听风的影响 |
|---|---|---|---|
| 息风剑印 | 西侧药圃 | `逐风归息`：追随三个移动静风眼完成守印 | 减弱风场推拉与持续时间 |
| 藏锋剑印 | 东侧藏剑廊 | `百剑归匣`：在交替剑架封路中击败守印精英 | 减少环行残剑组数与持续时间 |
| 照客剑印 | 南侧迎客亭 | `灯照来客`：依次转移到四处灯照区域完成守印 | 缩短追踪剑印锁定与追踪时间 |

具体流程、时间轴、敌群和验收见[青岚旧庭](Content/Maps/青岚旧庭.md)。

## 10. 首版局外资源提案

本节状态：`PROPOSED`

首版避免“每件内容一种碎片”，只保留以下五类概念：

| 名称 | 性质 | 用途 |
|---|---|---|
| 灵砂 | 唯一通用可消费软货币 | 一次性研习已发现公共器法、有限据点便利 |
| 行脉点额度 | 全账号共享、非消费配置容量 | 限制每名角色当前可激活的行脉节点总成本 |
| 角色阅历 | 每角色自动进度 | 解锁该角色节点、故事和挑战，不直接增加属性 |
| 脉标 | 唯一世界里程碑 | 记录主要秘境首通、稳定通路并推进据点和主线 |
| 器谱与心诀录 | 全账号发现记录 | 证明公共内容已经发现，使其可在百器阁研习 |

失败保留已取得灵砂、角色阅历和发现记录；只有满足主要胜利条件才建立脉标、推进主线并获得胜利
加成。完整用途、禁区和待验证问题见[局外成长模块](Systems/06_局外成长_资源与青岚旧庭.md)。

## 12. 技术与生产边界

本节状态：`ACCEPTED`

- 当前 Unity 框架已冻结到 M10；设计文档不是修改公共 API 的授权；
- 角色技、行脉图、双初始器法、地图目标、首通状态和轨迹回放等尚未被现有模块完整表达的部分，
  必须先提交 Change Request，并同步 ADR、Schema、存档、验证器、API 基线和测试；
- 具体角色、器法、敌人和地图不得在核心程序集按 ContentId 硬编码；
- 模拟层不依赖 Unity 对象，高频路径不用逐实体 `MonoBehaviour.Update`、LINQ、反射或临时集合；
- 用户可见文本使用本地化 Key；发布 ID 使用 canonical 小写稳定 ContentId；
- 框架期只用程序化 Placeholder，正式资产在玩法灰盒通过后按 provenance 和许可证流程制作。

## 13. 接下来的设计顺序

1. 评审基础构筑究竟采用几层、武器/心法槽位、最高等级和升级候选规则；
2. 定稿基础战斗、属性、受击、经验、拾取、即时灵物和显化补偿；
3. 定稿角色技输入状态、固有特性强度和行脉图节点/成本/额度；
4. 定稿敌人、精英、导演、地图目标、Boss 阶段和通用胜败接口；
5. 定稿结算保留、灵砂、角色阅历、脉标、器谱研习、据点与内容池管理；
6. 定稿难度阶梯、重访、角色试炼和挑战模式边界；

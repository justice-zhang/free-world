# 类幸存者游戏完整落地方案

## 1. 项目目标

建立一个独立、可商业化、可扩展的类幸存者游戏框架。框架完成后，团队应能持续新增角色、技能、被动、构筑联动、敌人、Boss、地图、波次、难度和局外成长，而无需反复修改核心系统。

项目不是开源游戏换皮，也不复用参考项目中的美术、特效、角色、地图、Prefab、Scene、动画、音频、字体、Shader 或品牌元素。所有正式表现资源后续通过自有生产流程创建，其中 AI 生成资源必须留存完整来源记录并经过人工审核。

## 2. 技术基线

| **领域** | **决策**                                                    |
|----------|-------------------------------------------------------------|
| 引擎     | Unity 6 LTS，锁定 ProjectVersion.txt 中的准确补丁版         |
| 渲染     | URP；初始支持 2D/2.5D 顶视角                                |
| 语言     | C#                                                          |
| 首发平台 | Windows x64 + Steam                                         |
| 输入     | Unity Input System；键鼠与主流手柄                          |
| 资源     | Addressables；本地 Catalog 起步，后续可扩展远程 Catalog/DLC |
| 本地化   | Unity Localization；简体中文、英文、伪本地化                |
| 测试     | Unity Test Framework；EditMode、PlayMode、Soak Test         |
| 性能     | 先正确的单线程数据导向实现，再按测量结果迁移 Jobs/Burst     |
| 平台     | IPlatformFacade 隔离；先用 Null 实现，后接 Steam            |
| 内容     | ScriptableObject 作者数据 → 验证/烘焙 → 纯运行时定义        |

## 3. 成功标准

框架完成后必须证明：

1\. 新角色可通过配置和资源新增，不修改核心程序集。

2\. 使用现有效果模块的新技能可完全通过配置新增。

3\. 新构筑由标签、条件、联动和进化配方形成，不创建硬编码“流派类”。

4\. 新地图由地图定义、场景、地图运行时和遭遇表组合完成。

5\. 表现资源可整体替换而不影响模拟规则。

6\. Steam 不可用时，本地版本仍可完整运行。

7\. 内容、存档和构建均有版本与校验机制。

8\. 正式构建无法混入 Placeholder 或无来源记录的正式资源。

9\. 固定随机种子的核心测试可复现。

10\. 压力运行没有持续内存增长或高频 GC。

## 4. 扩展等级

### 4.1 数据扩展

不修改核心代码即可新增：

- 角色、初始技能、角色 Trait

- 技能、被动、状态效果组合

- 敌人、Boss、掉落表

- 构筑联动、武器进化

- 地图、遭遇表、刷怪阶段

- 局外升级、解锁条件、难度

- 视觉与音频 Profile

### 4.2 逻辑模块扩展

遇到已有模块无法表达的新机制时，新增一个实现统一接口的模块并注册。例如时间倒流、伤害传播、分身重放、地图腐化。新增模块不得要求修改已有角色、技能或地图配置。

### 4.3 引擎后端替换

通过接口替换：

- 管理数组 → Jobs/Burst 后端

- SpriteRenderer → GPU Instancing

- 本地保存 → Steam Cloud 同步

- 有限竞技场 → 无限区块地图

- Unity 粒子 → 自定义 GPU 特效

上层内容格式保持不变。

## 5. 明确不做

框架阶段不做：

- 多人联机

- 运行时用户脚本 Mod

- 外部 C# DLL 热加载

- 正式剧情系统

- 大量正式角色或武器

- 在线账户、付费、排行榜

- 复杂 Steam SDK 集成

- 运行时生成 AI 美术

- 试图取代 Unity Entities 的通用 ECS

## 6. 工程原则

- 模拟层只认识数字、稳定 ID、运行时索引、标签和实体句柄。

- 模拟层不知道 GameObject、Transform、Prefab、Sprite、AudioClip、Scene 或 Steam。

- 表现层只消费快照与事件，不拥有战斗真值。

- 高频实体不使用逐实体 MonoBehaviour 更新。

- 不使用 GameObject.Find、FindObjectOfType、全局 Service Locator 或随意的静态 Singleton。

- 不在高频路径使用 LINQ、反射、字符串格式化或临时集合。

- 运行开始后，高频对象通过池和数据 Store 管理。

- 所有架构重大决策写入 ADR。

- 所有里程碑必须有可执行测试和可审计结果。

## 8. 商业化边界

- 根目录许可证不代表仓库中所有资产都拥有相同授权。

- 所有外部代码、字体、音频、插件和素材必须单独记录。

- 无许可证的公开仓库不能作为复制来源。

- 正式 AI 资源必须保存工具、模型版本、日期、提示词、输入引用、人工修改和文件 Hash。

- 上线前按当时最新的 Steam、引擎、插件与司法辖区要求复核；本文档是工程流程，不是法律意见。

# Change Request：完整 Run Recovery

- 编号：CR-2026-015
- 状态：Deferred
- 提交日期：2026-08-04
- 提交人：Codex
- 目标里程碑：Demo 后重新评审
- 关联 ADR：ADR 0015（延期边界）；对应 Demo CR-11

## 1. 变更摘要

完整任意 Tick 局内恢复延期到 Demo 后。当前 Demo 只检测不完整 `run_recovery.json`、显示本地化提示并由用户明确开始新局后清理，不提供“继续本局”。

## 2. 触发场景

- 用户或设计需求：未来可在崩溃或退出后继续长局。
- 当前限制：可靠恢复需要重建随机流计数、实体句柄、目标/Boss/奖励事务和版本迁移，当前 DOD 不要求。
- 可复现示例：只保存玩家属性会让恢复后的刷怪、奖励和阶段状态与原局分叉。

## 3. 现有模块为何不足

Save Backend 能原子写文件，但 SimulationWorld、运行时索引和句柄不能直接序列化；现有 Profile/Settings 存档也不承担局内快照。

## 4. 提议方案

- 新增或修改的模块：当前不新增完整恢复模块；仅保留 Recovery Marker 检测/清理边界。
- 公共 API：Demo 仅暴露不完整记录存在、清理和“开始新局”结果。
- 数据结构：标记只含版本、RunId 和不完整状态；不得含运行时索引或 Unity Object。
- 注册方式：未来重新提交 CR 和 ADR 后决定。
- 编辑器工作流：当前只验证检测、提示 Key、清理和禁止 Continue。

## 5. 影响分析

| 领域 | 影响 |
|---|---|
| Assembly 依赖 | 当前无新依赖 |
| Content Schema | 无影响 |
| Save Schema | 完整快照延期；标记不等于可恢复存档 |
| Addressables | 本地化提示使用现有流程 |
| 性能 | 当前仅启动时低频检查 |
| 测试 | 检测、提示、清理、不计胜利和无 Continue |
| 平台 | 未来需覆盖 Steam/本地中断写入 |
| 资产与许可 | 无影响 |
| 兼容性 | 不宣称已有 run_recovery 可继续 |

## 6. 备选方案

序列化整个 SimulationWorld 看似完整，但会保存不稳定索引、句柄和实现细节，无法安全迁移，因此禁止。

## 7. 迁移与回滚

- 迁移步骤：当前无完整迁移；未来需为随机流、实体、目标、Boss 和奖励事务定义稳定快照。
- 旧数据处理：检测到不完整记录只允许清理并开始新局，不得提交胜利/首通。
- 回滚步骤：移除检测 UI 时仍应安全忽略或清理标记，不能误读为 Profile。

## 8. 验收标准

- [ ] 未来机制不得序列化运行时索引/句柄
- [x] 当前 Demo 不显示 Continue
- [x] 当前自动测试覆盖检测、清理和禁止结算
- [ ] 完整恢复性能验证延期到重新评审
- [ ] 重新启用前新增 ADR、Schema 与迁移设计
- [x] 不破坏 Profile/Settings 存档

- 制作人：依据用户当前连续 Demo 开发指令记录延期

# 《剑起青岚》统一整合版完整游戏系统方案

- 文档版本：V1.0-integrated
- 文档日期：2026-07-30
- 产品形态：中国风俯视角动作 Roguelite / Survivors-like
- 首发平台：Windows x64 / Steam
- 商业模式：PC 买断制；首发不依赖在线服务，不设计付费数值成长
- 技术基线：Unity `6000.3.20f1`、URP、C#
- 文档定位：Demo 垂直切片、完整版 1.0 和后续扩展的统一产品基线

> 本文整合两份 Demo 方案和两份完整版方案。原稿保留作为设计来源，后续产品、内容与验收讨论
> 默认以本文为准；技术实现若与仓库规范冲突，以 `AGENTS.md`、已接受 ADR、
> `Docs/ARCHITECTURE.md` 和 `Docs/CONTENT_SCHEMA.md` 为准。

## 1. 四份原案分析与整合结论

### 1.1 原案各自价值

| 来源 | 主要优势 | 独有或更完整的内容 | 统一版采用方式 |
|---|---|---|---|
| Demo 方案 1 | 具体、可执行、表格完整 | 武器、心诀、显化、Boss 阶段、地标、时间轴和验收细节 | 作为 Demo 内容明细来源 |
| Demo 方案 2 | 边界清晰、结构紧凑 | 明确“不实现”清单、相机、碰撞、受击保护、动画最低集合 | 作为 Demo 范围与体验骨架 |
| 完整版方案 1 | 叙事和人物最丰富 | 九境域故事、Boss、九名角色机制、关系网和主题表达 | 作为世界、角色和剧情明细来源 |
| 完整版方案 2 | 产品治理最完整 | 游戏模式、区域内容包、经济边界、存档兼容、完成定义 | 作为完整版系统与交付骨架 |

### 1.2 四案共同核心

四份方案一致确认以下不可动摇的产品特征：

1. 清朗、有生命力的中国幻想，而非阴沉末日式修仙。
2. 移动、路线与空间判断是战斗的一部分，攻击以自动释放为主。
3. 角色不是属性皮肤，每名角色必须有本命器、独有机制和价值观。
4. 构筑语法由角色、天下百器、诸脉心诀、战场奇物与器法合鸣共同形成。
5. 地图不是背景图；地域目标、事件、路线和 Boss 都必须进入规则层。
6. 局外成长增加选择权和构筑控制力，不制造永久数值碾压。
7. Demo 是青岚旧庭的完整垂直切片，也是完整版的第一阶段，不是平行产品。
8. 正式版包含九名角色、八个主境域加天衡中枢，以及三种世界选择。
9. 内容必须数据驱动、使用稳定 ID，并能按区域扩展而不修改核心程序集。
10. 首发保持离线可玩，不引入联机、抽卡、体力、通行证或强制在线。

### 1.3 主要差异与统一决策

| 议题 | 原案差异 | 统一决策 |
|---|---|---|
| Demo 结构 | 方案 1 更细；方案 2 更强调排除项和底层规则 | 使用方案 2 的章节骨架，完整吸收方案 1 的内容表和验收条款 |
| 完整版规模 | 方案 1 偏首发可控下限；方案 2 偏完整愿景上限 | 同时保留“1.0 承诺基线”和“扩展目标”，不把愿景上限变成首发硬承诺 |
| 武器槽 | Demo 为 4 槽且本命器占 1；完整版方案 1 为本命器另列 | 数据上分为 1 个本命器槽和公共武器容量；Demo 公共容量 3，完整版公共容量 4 |
| 结局命名 | “旧衡复归/山海各行/青岚新路”与“复衡/共衡/开界” | 采用短名“复衡/共衡/开界”，旧名作为设计释义保留 |
| 据点关系设施 | “行旅亭”与“议脉亭” | 正式名称采用“议脉亭”，同时承担同行、关系和脉议功能 |
| 普通敌人数 | 48—60 与“50—60＋15—20 地域特殊敌人”口径不一 | 1.0 总量按 50—60 个敌人定义计，地域特殊角色包含在总量内，不重复相加 |
| DOTS/Jobs | 原案提出分阶段迁移 | 遵循现有架构：先保持已验证的数据导向单线程实现，只有性能证据要求时才申请 Jobs/Burst 后端 |
| 开发里程碑 | 原案从 M0 重建框架；仓库已完成 M0—M10 冻结 | 废止原案 M0—M5 编号，后续使用“内容阶段 G0—G6”，不重做框架 |
| 新内容类型 | 原案列出多种尚未进入当前 Schema 的定义 | 先映射到既有 Character/Skill/Passive/Trait/Synergy/Evolution/Enemy/Map/Encounter；不足时先提交 Change Request |

## 2. 产品愿景与设计支柱

### 2.1 一句话定位

玩家扮演在山海间自由行走的巡脉者，在由现实、灵脉和历史记忆重叠形成的中国幻想境域中自动
御器战斗，以天下百器、诸脉心诀和战场奇物形成流派，斩解灵结、连接诸域，并决定天下下一种
连接方式。

### 2.2 核心体验闭环

```text
选择角色与境域
→ 在有限手工地图中移动、自动攻击和探索
→ 获取经验，选择百器与心诀
→ 击败精英，取得改变本局规则的奇物
→ 完成地域目标，推动器法合鸣
→ 击败中段 Boss 和最终 Boss，斩解灵结
→ 带回灵砂、脉印、故事、藏品和角色经验
→ 复苏青岚旧庭，增加下一局的选择权
→ 推进主线并决定天下如何重新连接
```

### 2.3 五项设计支柱

#### 清朗中国幻想

- 即使出现废墟、灾难和执念，也必须保留阳光、草木、生活痕迹和自然生长。
- 地域差异来自地理、行业、生活方式、技艺和价值观，不只来自换色。
- 避免把阴暗、尸骸、末日和苦难作为唯一审美资源。

#### 角色决定玩法逻辑

每名角色至少具备：本命器、独有机制、专属行脉图、完整故事、关系冲突和终式显化。选择角色
应同时改变战斗节奏与理解世界的角度。

#### 世界内容直接进入构筑

- 天下百器来自宗门、城镇、行业、自然与地方技艺。
- 诸脉心诀描述力量如何运行。
- 战场奇物改变本局规则。
- 器法合鸣把器物来源、心诀路线和角色机制连接为最终流派。

#### 地图差异进入规则层

每个境域必须拥有独立空间结构、地域目标、动态事件、敌人生态、Boss 规则和视觉/音频语言。
探索偏离安全路线时，应带来明确的局内收益、局外收益或叙事发现。

#### 局外成长保持克制

长期成长主要提供候选控制、角色路线、信息、内容解锁与有限容错。禁止通过无限永久攻击、生命
叠加，让局外数值替代局内判断和构筑。

## 3. 世界观总纲

### 3.1 天衡十二脉

旧时代建造了连接天下的十二条巨型灵脉网络“天衡十二脉”。它传递灵气，也调节季候、水汽、
交通、物产和信息。天衡带来繁荣，却逐渐把不同地域的语言、技艺、生态与生活方式压缩成统一
标准。

### 3.2 断衡之变

百年前，青岚宗发现天衡即将失控并造成彻底同化，参与斩断部分连接。断衡阻止了更大的灾难，
却使现实与积累在灵脉中的记忆、技艺、愿望和自然力量相互重叠，形成拥有独立规则的“境域”。

### 3.3 灵结、斩结与剑

现实与记忆、过去与现在、人与自然、愿望与事实纠缠成“灵结”。普通术法只能压制，巡脉者则
通过理解矛盾、完成地域目标并击败灵结核心来“斩结”。

剑在本作中代表分界、选择和决断。斩结不是消灭所有异类，也不是把一切恢复原状，而是让被困
在旧规则中的存在重新拥有变化的可能。

### 3.4 主要势力

| 势力 | 主张 | 优点 | 风险 |
|---|---|---|---|
| 守衡司 | 恢复旧天衡 | 重视稳定、公共秩序和灾害控制 | 可能再次压缩地方差异与个人选择 |
| 百工联社 | 研究并利用境域 | 重视技术、生产、贸易和现实改善 | 可能把生命、记忆和地域只当作资源 |
| 山海盟约 | 各境域自行决定未来 | 尊重地方自治、生态与传统 | 可能导致割裂、冲突与连接中断 |
| 新青岚 | 建立非中心化的巡脉网络 | 在连接与自主之间寻找新结构 | 需要持续协商，无法依赖唯一权威 |

### 3.5 三幕主线与三种尾声

1. **第一幕·断路**：青岚旧庭、赤炉天工城、镜海沉市。玩家确认天衡是旧文明建造的系统。
2. **第二幕·诸域**：霜钟、金砂、云鲸、百戏、万菌。玩家理解断衡后出现的新生命和新文明。
3. **第三幕·新衡**：天衡中枢。玩家确认青岚宗旧日选择，并决定天下未来的连接方式。

| 尾声 | 旧案释义 | 决策含义 |
|---|---|---|
| 复衡 | 旧衡复归 | 恢复中心化秩序，快速稳定，但地方差异再次收缩 |
| 共衡 | 青岚新路 | 建立分布式灵脉，各地共同维护连接，接受协商与不确定性 |
| 开界 | 山海各行 | 诸域自治，只开放自愿连接的脉门，更自由也更脆弱 |

承担。

## 5. 完整游戏模式与单局结构

### 5.1 游戏模式

| 模式 | 定位 | 首发优先级 |
|---|---|---|
| 巡脉主线 | 18—22 分钟标准剧情关，含地域目标、中段 Boss 和最终 Boss | 必须 |
| 境域重访 | 主线后自由选图，用于收集、故事和构筑挑战 | 必须 |
| 脉潮等级 | 0—10 级递增难度，改变敌群、事件和规则而非只加血 | 必须 |
| 境域异变 | 玩家主动叠加挑战词条 | 必须 |
| 角色试炼 | 围绕每名角色的独有机制设计 | 必须 |
| 长途远征 | 连续挑战三个境域，跨关保留部分构筑与境域遗器 | 完整版必须 |
| 演武场 | 武器测试、伤害统计、Boss 练习和教学 | 完整版必须 |
| 无尽灵潮 | 极限构筑与性能挑战 | 1.0 后可选，不阻塞首发 |

### 5.2 槽位与成长等级

- 本命器槽：固定 1 个。
- 公共武器容量：Demo 3 个，完整版 4 个。
- 心诀槽：4 个。
- 战场奇物槽：3 个。
- 普通武器：建议 8 级。
- 心诀：建议 5 级。
- 奇物：最多 3 级或以稀有升级替代，具体由内容验证确定。
- 升级选牌默认 3 选 1，选择时只暂停 SimulationClock。

### 5.3 典型 20 分钟完整版节奏

| 时间 | 阶段 |
|---|---|
| 0—4 分钟 | 建立基础构筑、探索首区 |
| 4 分钟 | 第一精英 |
| 6—8 分钟 | 地域事件与首个主要目标 |
| 10 分钟 | 中段 Boss 与显化宝匣 |
| 11—15 分钟 | 地域规则强化、复合敌群 |
| 15 分钟 | 第二精英或区域挑战 |
| 18 分钟 | 高压敌潮 |
| 20 分钟 | 最终 Boss |
| Boss 后 | 结算、故事、藏品与脉印 |

## 6. 战斗与构筑系统

### 6.1 操作、相机与碰撞

- 移动：键鼠 WASD/方向键，手柄左摇杆。
- 攻击：自动释放；不设置通用攻击键和通用闪避键。
- 地图、暂停、确认、取消和页签均提供键鼠/手柄绑定。
- 正交俯视或轻斜俯视相机，角色略低于屏幕中心，平滑跟随并限制震动强度。
- 玩家可穿过普通敌人但承受接触伤害；普通敌人不能形成完全不可穿越的物理墙。
- 普通接触伤害保护建议 0.6 秒；Boss 高危技能使用独立、清晰预警的伤害通道。

### 6.2 公共属性与伤害规则

公共属性限定为：最大生命、生命恢复、护甲、移动速度、威力、攻击间隔、作用范围、持续时间、
投射物速度、投射物数量、穿透、暴击率、暴击伤害、击退、拾取范围、经验获取和幸运。

伤害、护盾、状态、死亡和事件必须经过仓库既有 M3 管线。幸运不能影响首次 Boss 脉印、唯一剧情
物品或其他确定性进度奖励。Demo 使用灼烧、中毒、减速、定身、标记、破甲和击退；Boss 不可被
完全冻结或无限控制。

### 6.3 天下百器

公共武器分为六类：

- 剑器：追踪、穿刺、回返与高速连击。
- 符箓：标记、引爆、条件触发与阵域。
- 机关：召唤、部署、回旋与生产节奏。
- 法器：环绕、领域、吸附、击退与周期变化。
- 异宝：幻象、位移、交换和高风险规则。
- 草木灵物：生长、持续伤害、治疗和共生铺场。

### 6.4 诸脉心诀

| 类别 | 主要作用 |
|---|---|
| 心诀 | 攻击、冷却、暴击和稳定性 |
| 身法 | 移动、转向、闪避宽容和穿行 |
| 炼体 | 生命、防御、恢复和护盾 |
| 驭器 | 数量、穿透、投射速度和召唤物 |
| 阵法 | 领域、范围、持续时间和控制 |
| 观想 | 经验、幸运、掉落和构筑控制 |
| 调脉 | 节奏、资源循环和状态稳定 |
| 异修 | 低生命、代价、限制条件和高风险高收益 |

### 6.5 器法合鸣

标准显化条件为“满级武器＋指定心诀达到要求＋取得显化宝匣”。层级包括：

1. **标准显化**：任何角色均可完成，一器一法形成主要流派闭环。
2. **本命显化**：原角色使用本命器时，额外联动角色机制。
3. **终式显化**：完成角色故事、激活终端行脉节点并满足局内条件后改变武器行为。
4. **双器共鸣/境域显化**：只用于少量隐藏构筑，不成为普遍规则。

标准显化优先用现有 `Evolution` 表达，条件联动优先用 `Synergy` 表达。无法组合表达的双器、终式
或境域规则必须先提交 Change Request，不得按具体武器 ID 在核心程序集硬编码。

### 6.6 随机池管理

- 角色亲和：提高与本命机制相合内容的权重。
- 地域权重：提高当前区域武器、心诀和奇物的权重。
- 流派倾向：出发前选择 1—2 个标签倾向，但不保证指定武器。
- 封存：临时关闭少量已解锁内容。
- 刷新、放弃与 Banish：次数有限，由成长或构筑提供。
- 新内容保护：新解锁内容在随后数局获得适度权重。

### 6.7 局内道具层级

1. **即时战斗灵物**：接触即触发，解决回血、清场、吸取、免伤和短时移动问题。
2. **精英战场奇物**：改变本局规则，精英死亡后通过异相灵核 3 选 1。
3. **中段 Boss 境域遗器**：普通关服务后半局；远征可跨关保留。
4. **最终 Boss 奖励**：永久脉印、唯一藏品、故事、角色或功能，不掉只在本局生效的遗器。

## 7. 敌人、导演、地图与 Boss

### 7.1 敌人生态

每个区域至少覆盖群聚、追袭、重甲、远程、支援、环境/自爆等功能角色。敌人通过组合产生压力，
不能依赖无限生命或纯数值膨胀。

精英由基础敌人、1—2 个词缀和地域强化组成。词缀分为行动、防御、区域和死亡四类；每个词缀
必须有明显轮廓、颜色、前摇和音效，互斥组合要在内容验证阶段拦截。

### 7.2 刷怪导演

导演由三层构成：固定节奏骨架保证叙事与 Boss 时点，预算组合系统根据阶段生成敌群，保护规则
避免场上实体异常或出生点不公平。保护规则不得动态惩罚高输出玩家，也不能用全屏不可读伤害
伪造难度。

### 7.3 地图原则

- 主要关卡使用大型有限手工地图。
- 地图包含约 5 个清晰子区域、地域规则、主要目标、3—5 个事件与多个兴趣点。
- 事件、精英、部分地标和收集位置从预设锚点中变化。
- 地域目标不能要求玩家长时间停止战斗；互动期间继续移动、防守或完成区域击杀。
- 地图收集不使用极低概率唯一掉落，必须提供可追踪线索。

### 7.4 Boss 原则

Boss 至少采用三阶段，或两阶段加终结阶段；阶段切换必须改变空间、节奏或规则。Boss 可被减速、
标记、破甲等系统影响，但使用抗性和递减避免永久控制。击败 Boss 的叙事含义是解开一个灵结，
而不是消灭一个纯粹邪恶的血条。

## 9. 局外系统与长期重玩

### 9.1 青岚旧庭据点

完整版设施包括脉图台、藏卷楼、百器阁、万象阁、百工台、灵圃、演武场和议脉亭。设施由主线、
角色加入和地域复苏逐步变化，不发展为自由建造或资源挂机游戏。

### 9.2 经济边界

只保留两种主要资源：灵砂和境主脉印。角色经验是进度值，不是第三种消费货币。禁止多层材料、
随机装备词条、强化失败、每日任务和无限资源循环。

### 9.3 角色成长、故事与收藏

- 每名角色拥有本命、身法、心性三支行脉图；节点可逐步解锁，但出发时可激活数量有限。
- 每名角色建议 6 个主要故事篇章，奖励以外观、对话、终式条件和内容解锁为主。
- 收藏分百器遗珍、灵植异种、地域遗物、人物旧物和天衡残片。
- 完整版剑匣固定攻势、护行、探寻 3 槽，模块改变规则或构筑控制，不提供无条件永久碾压。

## 11. UI、可访问性、美术与音频

### 11.1 UI 信息架构

主要界面包括标题、存档、角色/地图选择、加载、战斗 HUD、暂停、设置、升级、结算、据点设施、
故事/收藏、演武场和内容错误页。升级卡必须显示名称、等级、行为变化、标签和与当前构筑的关系，
不能只显示百分比。

### 11.2 可访问性

至少支持键位重绑、键鼠与手柄、摇杆死区、震动强度、屏幕震动、闪光强度、伤害数字、自动瞄准
策略、字体大小、色觉区分和简中/英文/伪本地化布局验证。

### 11.3 美术方向

- 2D/2.5D 俯视，角色轮廓优先，不让所有角色落入同一年龄与体型模板。
- 地域色彩必须显著不同；玩家攻击与敌方危险色域分离。
- 特效存在层级与透明度预算，同屏高成本效果有优先级。
- 正式资产必须原创或具备明确商业授权；AI 资产保留工具、模型、提示词、输入引用、人工修改和 Hash。

### 11.4 音频方向

每区至少包含环境层、探索音乐层、常态战斗层、高压层、Boss 层和标志性环境声。角色机制、精英
词缀、Boss 高危技能和显化必须有可辨识声音提示，并提供独立音量设置。

## 12. 与现有 Unity 框架的实现对齐

### 12.1 强制技术基线

- Unity 精确版本为 `6000.3.20f1`，URP，Windows x64 / Steam 首发。
- 模拟固定 30 Hz，表现目标 60 FPS 或更高。
- 使用 Input System、Addressables、Localization 和 Unity Test Framework。
- `Game.Core` 与模拟层不引用 UnityEngine；表现只消费快照和事件。
- 高频实体使用稠密 Store、统一空间网格和集中系统，不使用逐敌人 `MonoBehaviour.Update`。
- 不使用 `Resources.Load`、场景查找、全局 Service Locator、DOTween、Odin 或第三方 DI。
- 不提前迁移 Jobs/Burst/ECS；只有可复现 Profiler/基准证据证明必要时才提交后端变更。

### 12.2 产品概念到现有内容 Schema 的映射

| 产品概念 | 优先映射 |
|---|---|
| 角色、本命机制 | Character＋Starting Skill＋Trait |
| 天下百器/本命器 | Skill；Trigger＋Targeting＋Delivery＋Effects＋LevelPatches |
| 诸脉心诀 | Passive、Trait 和 Modifier |
| 器法合鸣 | Synergy＋Evolution |
| 状态、词缀行为 | Status＋通用 Modifier/Effect 组合 |
| 普通敌人/Boss | Enemy＋Skill＋Encounter BossRules |
| 境域、地图目标与时间轴 | Map＋Encounter＋锚点/通用事件模块 |
| 解锁、行脉、收藏、剑匣 | 优先组合既有稳定 ID、Trait、Unlock 和存档边界；不足时提交 Change Request |

任何无法由现有模块表达的新机制，必须说明通用价值、Schema/存档/性能影响、迁移与回滚方案，
不能在陆青野、某把武器或某张地图的专用类中硬编码。

### 12.3 稳定 ID 与内容包

- 所有正式内容保存 canonical 命名空间 ID；显示名只使用 Localization Key。
- 存档保存稳定 ID，不保存 RuntimeContentIndex 或 Unity Object。
- 区域可组织为独立 Pack，例如 `region.qinglan`，但正式 Pack ID、依赖和版本须在作者任务中验证。
- 内容构建前执行引用、等级、概率、显化可达性、本地化、Placeholder、provenance 和许可证检查。
- 原案中的 ID 与类型名均是产品草案，不自动视为已发布 ContentId 或已批准 Schema。

### 12.4 存档与平台

存档必须支持版本迁移、校验、备份、损坏回滚、缺失内容拒绝/降级和稳定 ID。首发本地文件是真值；
Steam、云存档、成就和 Rich Presence 通过平台抽象接入，平台不可用时仍可完整离线游玩。

## 13. 性能、测试与发布门禁

### 13.1 性能口径

- 产品目标：1080p 60 FPS；Demo 的 1% Low 低于 45 FPS 时触发警报。
- 正常内容目标：600—1200 活跃普通敌人、400—900 投射物/领域；2000 敌人是扩展压力目标。
- 框架已有 M10 纯模拟证据：1,500 敌人、3,000 投射物、5,000 拾取物，30 分钟 54,000 Tick，
  Tick p99 10.9851 ms、热路径 0 B、0 GC、无持续内存增长。
- 上述 M10 Render 数据来自 Null Device，不能替代正式角色、Shader、VFX 和目标 GPU 的实机基线。
- 2000 敌人、正式资产 GPU Frame Time 和全内容长时间运行在本文任务中均为 `NOT RUN`。

### 13.2 测试体系

- EditMode：伤害、属性、状态、随机、候选、Synergy/Evolution、内容验证、存档迁移。
- PlayMode：完整页面流、角色输入、升级暂停、地图目标、Boss 阶段、结算、语言和手柄。
- 内容验证：ID、引用、等级、概率、互斥、显化可达性、本地化、资产来源和 Release 标签。
- Soak/性能：固定种子、目标规模、帧时间、Tick 分位、GC、内存趋势和对象池命中。
- 构建：Windows Development 与 Release，Release Player 冒烟，离线平台路径和 Manifest。

所有结果只使用 `PASS`、`FAIL`、`NOT RUN`；没有日志、XML、JSON、Manifest 或 Player 证据时不能
写成通过。

## 15. 明确不纳入核心范围

- PVP、实时联机、MMORPG 式装备强化和随机词条背包。
- 角色抽卡、体力、每日任务、通行证和付费数值成长。

## 16. 完整版完成定义

完整版只有同时满足以下条件才可称为完成：

1. 九个主要境域均具备独立规则、目标、敌群、Boss、视听语言和完整结算。
2. 九名角色均具备本命器、独有机制、行脉图、完整故事和终式方向。
3. 武器、心诀、奇物与显化形成稳定、可解释、可控制随机池的构筑语法。
4. 局外成长提高选择权，不替代局内判断。
5. 主线、角色故事、地图叙事、藏品和三种尾声相互连接。
6. 主线、重访、脉潮、异变、角色试炼、远征和演武场可独立运行。
7. 存档可迁移，平台不可用时仍能完整离线游玩。
8. 所有内容 Pack 通过自动验证，正式资产具备 provenance 与许可证记录。
9. 键鼠、手柄、本地化和可访问性达到发布标准。
10. 正式内容环境中的性能、Soak、Development/Release Build 和 Player 冒烟均有真实证据。
